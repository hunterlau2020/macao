## 0. 评审原则 (Principles)

1. **证据先行**:每条发现必须给出 `file:line` 定位与可复现的反例输入或调用序列;没有证据的"闻起来不对"写入疑问清单,不占缺陷条目。
2. **证据 > 票数**(R17):合并决定是**证据标签的函数,不是票数的函数**——任何多数派结论都盖不过一个带反例的发现;多模型评审结果只作建议性输入,由属主签字环节兜底。
3. **独立复现优先 + 冲突四步**(R3):两家结论相反时——①复现实验;②事实与定级分离查表(§0.2);③环境声明与 CODE 声明分开打标;④属主裁决。
4. **等价类闭合**(R4):修复验证轮关闭同一声明的等价绕过即闭合(有数学闭合的不得再以更花哨拼图否决);**新的不同声明另开条目**,不得借旧条目重开。
5. **前提重核 + 区间文件归属**(R14):评审基线若已越过申请基线,报告记 `git rev-parse HEAD` + `git diff <base> HEAD --stat`;**评审区间内每个文件须归属**(受评/不评+理由/意外落入+处置),"非实现代码"不是豁免理由。
6. **分级查表,不查观感**:按 §0.2 判定表 + 定级三步留坐标;废止一切"拿不准降一级"式散文规则。
7. **区分缺陷与决策**:已接受的 MVP 边界(§1.2 / STATUS)不记为缺陷;不可接受时单列"决策项"由属主裁定,不得由代码默认行为或评审多数代替。
8. **验证修复,而非重复发现**:标注"已修复"的条目,评审动作是**构造反例击穿修复**(突变对照优先),不是重报原缺陷。
9. **儿童安全语境加权**:提示注入、NPC 人设、PII 最小化、内容适当性权重高于一般应用;儿童内容出库到外部 LLM 的路径,授权必须先于调用。
10. **Required action 可落地**:给出最小修复方向;接受权宜之计必须写明"生产化前需补什么"。

## 0.2 分级判定表(R2;表体按裁决 §二 v3)

**有声表**(缺陷有错误信号/日志/显性症状):

| 后果 \ 可达性 | 1 单方可触发 | 2 需误配置/泄露凭据 | 3 需刻意反常 |
| --- | --- | --- | --- |
| **A** 越权/泄露/儿童 PII/不能启动 | P0 | P0 | P1 |
| **B** 完整性·注入·契约破坏(含"已声明可重试的写路径双计") | P1 | P2 | P3 |
| **C** 安全控制失效无直接数据后果 | P2 | P2 | P3 |
| **D** 学习算法/边界正确性 | P2 | P3 | 观察 |
| **E** 可用性/运维/可维护性 | P3 | P3 | 观察 |

**静默表**(无错误信号、无日志、功能表面正常——A-D 类整体上移一级、封顶 P1;E 类"静默"是常态,不上调):

| 后果 \ 可达性 | 1 | 2 | 3 |
| --- | --- | --- | --- |
| **A** | P0 | P0 | P1 |
| **B** | P1 | P1 | P2 |
| **C** | P1 | P1 | P2 |
| **D** | P1 | P2 | P3 |
| **E**(不适用上调) | P3 | P3 | 观察 |

**定级三步(每步留痕)**:
1. 判根因:**当批引入或当批触及该路径** → 按症状查表(静默查静默表);**根因既有且本批未触及** → 一律查有声表并标注"根因既有"(R15);
2. 报告留一行坐标(如 `B/2/静默 → P1`),使定级可被一眼复算;
3. 表判不了的新型后果 → 决策项,属主裁一次,同轮把该情形补进表(R12)。

**三级标签 + 绑定门禁(R1/R16)**:结论 = 阻断(本批必须修)/ 应修(台账 + 绑 G-合并|G-硬件|G-发布 之一,到门禁时升级为阻断)/ `Nit:`≤3(不绑门禁)。"通过"不得挂必修项。P0/P1 不可作为已接受风险(R8)。

## 0.5 两轴证据标注(R13)

- **轴一 验证状态**(三态):`已复现` / `未验证(必写原因)` / `已证伪`;
- **轴二 契约符合性**(四值):`CONFORMS` / `VIOLATES(§章节)` / `UNDECIDED(决策项)` / `NO_CONTRACT`;
- **两轴独立标注、禁止互相推断**;`TEST` 只证明行为不证明合规(绿测试可以钉死违约行为);
- `VIOLATES` + 根因当批 → 阻断;根因既有 → 台账绑门禁。`NO_CONTRACT` → 同轮补契约草案(R12)。

## 0.6 声明验证矩阵(R10)

含具体数字或绝对措辞的**强声明一律进矩阵**,引用契约章节号;作者测试声明默认"未验证",评审方独立重跑后方可"已复现":

| # | 矩阵行 | # | 矩阵行 |
| --- | --- | --- | --- |
| ① | 幂等重试(同键重放不双计) | ⑤ | 状态流转(契约 §6 状态机) |
| ② | 终身一行(唯一约束兜底) | ⑥ | 跨端点同键独立捕获 |
| ③ | scope 隔离(契约 §4 矩阵) | ⑦ | 跨资源同键独立捕获 |
| ④ | 多解析器/多方言分支一致 | ⑧ | 同键并发·重叠在飞(409,不双执行) |

## 0.7 评审自审十条(R11;安全·状态机·写接口档强制,报告末尾填表)

①多解析器判据一致 ②状态写入覆盖重试/并发/事务失败 ③唯一索引冲突有业务处理 ④作者"已验证"有独立证据 ⑤不止查 happy path ⑥主动降级须覆盖全部变体(含等价绕过闭合) ⑦结论相反时核对对方事实 ⑧列阻断的每条真满足判据 ⑨契约/指南"已写但未实现"条目是否被当已知简化跳过 ⑩测试建的库/环境形态与部署形态一致(create_all vs migrate / SQLite vs MySQL / StaticPool vs request-scoped)。

## 1. 待评审范围 (Scope)

### 1.1 在评审范围内 (In scope)

整个 `backend/` 后端(路由分组/表数/模块数随版本演进,以 STATUS.md 基线为准):

- `app/api/v1/endpoints/` — 所有 HTTP 端点(鉴权、入参、响应一致性)
- `app/services/` — 业务逻辑(正确性、副作用、事务)
- `app/models/` — 数据模型(字段、约束、外键、JSON 列)
- `app/seed/` — 词库 ETL 与种子装入;`app/core/` — 枚举、安全原语、时间
- `app/workers/`、`scripts/migrate.py`(迁移脚本口径独立:仅去重/回填,必须幂等 + 记录删除行数)
- `tests/` — 测试充分性与 e2e;`frontend/` 仅静态回归

### 1.2 已接受边界(与 STATUS 互链)

**绑门禁/失效条件的开放项在 `docs/STATUS.md`(唯一权威)**;下表仅列不绑门禁的静态 MVP 边界,评审视为已接受,不记缺陷(认为不可接受 → 决策项):

| 项 | 现状 |

## 3. IDOR / 越权复核清单 (Concrete checklist)

| `POST /shadow/{id}/score` `retelling/writing/{id}/submit` | SessionItem | 会话归属 | 各 endpoint |
| `POST /scenario-weeks/{id}/start-day` `/review` | ScenarioWeek | `week.user_id == current_user` | `scenario.py` |

| `POST /emails/{id}/tips` | Email | 只能基于**发给自己的信**取回信建议 | `emails.py` |

| `POST /rewards/{id}/confirm|reject` | Redemption→RewardItem | `_assert_family_access` | `parent.py` |

> ⚠️ 任何"只校验认证、未校验资源归属"的端点都是 A 类缺陷(P0/P1)。
> **工程约定(历轮裁定新增)**:
> 1. **禁止裸 SQL 写 `pen_pals`** —— 好友关系创建/变更/复活必须走 `bind_penpal`/`unbind_penpal`(全部业务守卫)或受审计管理脚本;已知合法旁路仅两处:信箱惰性补齐(`penpal.mailbox`)、结构迁移脚本 `scripts/migrate.py`(必须幂等 + 记录删除行数)。
> 2. **枚举列裸 SQL 比较须用成员名** —— `SQLEnum` 存枚举**名**(`ADULT`/`PRIMARY`);(二十一) `age_band='adult'` 永假缺陷即前车之鉴。
> 3. **两侧判据逐字对齐,对不齐必须出声** —— 凡两处对同一输入各自解析/校验(邀请码、.env、IP 白名单),判据必须与真正消费方逐字一致;无法对齐处打印告警,不得静默回落。

## 6. 三道门禁(D1)+ MySQL 分层(D2)

| 门禁 | 时点 | 判据 |
| --- | --- | --- |
| **G-合并** | 每批合入 main | 申请模板(§8)齐全 + 强声明矩阵全绿(SQLite 可复现即算)+ 无未绑门禁的阻断项 |
| **G-硬件** | 硬件端点组(STATUS 清单)固件依赖前 | G-合并 + **幂等八行矩阵全绿**(§0.6 ①-⑧;⑧=同键并发交错语义,SQLite 可复现:占位先行+409/503)+ 列举面闭环(404 防枚举)。**MySQL 双连接真并发与行锁/RR 语义一律归 G-发布**(TEST-1,五十 gpt P1-3 拆分裁定——单一门禁归属,判据可确定性执行) |
| **G-发布** | 对外发布/生产部署 | G-硬件 + MySQL 8 集成测试存在且绿(契约 §7.6 `[target]` / A8 三步)+ STATUS 无 P0/P1 |

**MySQL 分层(D2,否决一刀切)**:① 触及 `with_for_update`/原子 UPDATE/upsert 路径 → 合并前须有能证明冲突处理的 TEST(**SQLite 能覆盖的唯一索引 + IntegrityError 重放算数**);声明依赖 MySQL 行锁的最多 PARTIALLY_VERIFIED 并登记"发布前补" ② 新硬件写路径(grade/drill 类)→ 合并门禁须有 SQLite 可复现重试双计回归 + 冲突不 500;行锁/RR 语义归 **G-发布** ③ 在 `pytest.mark.mysql` + 可选作业出现前,契约 §7.6 不得作为任何门禁判据(伪 TEST 防护)。

### 8.2 靶向变更清单(grok 反馈落地)

- 每行为级改动点一行:`文件:行区间 | 函数 | 行为变化一句话 | 波及面`——**行区间不得省**;
- "相邻但未改"高危邻居清单为**强制列**;
- **"零改动"不得覆盖被调用的叶子**:被调函数有行为变化时,不得在调用方行写"零改动"而不列叶子;
- 防操纵:清单是导航辅助**不缩小评审范围**;漏列视同未声明行为变化按当批引入定级;禁"重构/清理"聚合词。

### 8.3 测试脚本与质量快照

- 定向用例**必须写全限定 node id,禁止只写类名**(历史追加使新用例物理落入不相干类);脆性缓解可评估 `-k`/专用 marker(kimi);
- 差值账四态:新增/改写/折叠/未动;折叠必须在改写说明出现;改写用例附"原用例为什么测不到";
- 快照 = 作者自报,评审方复跑后才可"已复现";覆盖率只作趋势不作门禁。

### 8.4 开发者自评与审查聚焦点

- 自评三档:最有把握 / **最没把握(≤3 处,强制——留空退回;写"无"须对照 R11 ⑨⑩逐条论证)** / 我知道没测到的;
- **最没把握只写条件交点,禁止夹带未验证结论**(grok:自评出现具体数字/绝对措辞而未进 §1 矩阵,视同漏声明);
- 聚焦点 = 建议起点**非范围限制**;未列区域漏检责任仍在申请方;
- 形态差距(R11-⑩)须**点名哪条断言在哪种夹具上会失效**,不只写"测试是 SQLite";
- 禁止自评降级预埋:已知缺陷不得写成"取舍/边界"规避映射表定级。

### 8.5 结果模板对称格(强制)

内容以 **§5 三格**为唯一权威(单一真相源,五十 claude Nit-2 去重):①是否核了全区间 diff(不只靶向清单);②快照是否独立复跑(命令+输出摘要);③申请"最没把握"各处是否构造了反例。
