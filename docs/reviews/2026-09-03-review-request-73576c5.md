## 1. 评审背景与本轮闭环说明

在 `cd285dd` 评审轮中，委员会对用例体系（轨 B）给予了高度肯定并维持全票通过；针对设计同步（轨 A）提出的全部阻断项，架构团队已在 `73576c5` 彻底完成物理闭环、契约加固与自动化测试：

1. **根 `macao.yaml` 策略 Quorum 与 D-6 运行时校验语义对齐（Grok P1-1 / Qwen P1-1 / Claude A-P1-2 / Codex P1-1）**：
   - 仓库根 `macao.yaml` 原配置 4 名审查员，但配置了 `seat_quorum_required: 2` 与 `weight_quorum_required: 2`，低于 $\lceil 2 \times 4 / 3 \rceil = 3$ 的法定人数门禁，触发 `validate_config()` 拒绝；
   - 修正 `macao.yaml`：将 `seat_quorum_required` 与 `weight_quorum_required` 正确设定为 `3`；
   - `ConfigManager` 增加 `@property seat_quorum_required` 与 `@property weight_quorum_required` 属性；
   - 在 `tests/test_config.py` 中增加 `test_root_macao_yaml_passes_semantic_validation`，验证根配置同时通过 Draft-07 Schema 与全套语义校验（10/10 PASS）。
2. **提案 §4.2 表格残余“当前状态（HOLD）”及链接规范化（Claude A-P1-1）**：
   - 清理 `docs/PRD_CHANGE_PROPOSAL_v2.5.md` L128-129 残余表述，统一规范为 `` `CONSENSUS_CHECK`（HOLD） ``，全文档“当前状态（HOLD）”残留归零；
   - 将 L514 处绝对文件链接替换为相对链接 `MACAO_PRD_v2.md`。
3. **`review_disposition.schema.json` 顶层与嵌套全量封闭（Claude A-P2-3 / Codex P2-1）**：
   - 在 `docs/schemas/review_disposition.schema.json` 与 `src/macao/schemas/review_disposition.schema.json` 中为根对象、`executor`、`full_document` 以及 `dispositions.items` 全量追加 `"additionalProperties": false`；
   - 增设反例 fixture `disposition_unrecognized_property.yml`，并在 `tests/test_schema.py` 中断言精确拒绝。
4. **`ConsensusEngine.evaluate()` 纯整数加权 2/3 五道门禁实装（Codex P1-1 / Claude A-P1-3）**：
   - 废除浮点数除法比对，彻底重构为纯整数交叉乘法五道门禁：
     - Gate 2: $E_N \ge \text{seat\_quorum\_required}$
     - Gate 3: $E_W \ge \text{weight\_quorum\_required}$
     - Gate 4 & 5: $3 \times W_{\text{yes}} \ge 2 \times E_W \land S_{\text{yes}} \ge \text{minimum\_winning\_seats} \implies \text{APPROVED}$
     - Gate 4 & 5: $3 \times W_{\text{no}} \ge 2 \times E_W \land S_{\text{no}} \ge \text{minimum\_winning\_seats} \implies \text{REWORK\_REQUIRED}$
     - 其余一切情形 $\implies \text{DEADLOCK}$
   - 在 `tests/test_consensus.py` 中新增 Codex 反例测试 `test_weighted_counterexample_deadlock`（`[YES w=2, NO w=1, NO w=1]` 确凿产出 `DEADLOCK`）与 `test_weighted_minimum_winning_seats_enforcement`。
5. **`vote_result.schema.json` 契约强化与生成器对齐（Claude A-P1-3, A-P1-5 / Codex P1-3）**：
   - Schema 顶层 `required` 强制要求 `generated_at`、`task_id`、`executor_id`，并封闭根对象与各嵌套项（`additionalProperties: false`）；
   - `resolution` 枚举收敛为 `["AUTO_WEIGHTED_CONSENSUS", "HUMAN_OVERRIDE"]`；
   - `vote.py` 为每张选票自动填充 `source`（`manifest` / `timeout`）与 `weight`；
   - `reviewers_responded` 精确统计 `source == "manifest"` 票数，`reviewers_accounted` 统计全量选票；
   - `issues_index_sha256` 基于规范化 JSON 实时计算真实 SHA-256 哈希；
   - 新增反例 fixture `vote_result_missing_source.json` 并纳入全量测试。
6. **编排器 E4 守卫与 Type E `DISPOSITION_REQUIRED` 发布（Claude A-P1-4 / Codex P1-2）**：
   - `Orchestrator.collect_and_evaluate_consensus`：当裁决为 `APPROVED` 且存在 issues 时，严禁直接跳转 `MERGING`，必须停驻于 `CONSENSUS_CHECK` 并发布 Type E `DISPOSITION_REQUIRED` AEP 消息；
   - 增加 `submit_disposition()` 接口与 E5a 返工转移支持；只有当存在合法 FINAL disposition 且所有项目 `requires_new_checkpoint == False` 时，才允许 E4 转移至 `MERGING`；
   - 在 `tests/test_p0_p1_rectification.py` 中新增全链路端到端集成测试 `test_approved_with_advisory_holds_and_requires_disposition`。
