## 一、P1 核心阻断项逐项处置与闭环明细

### P1-51fa456-01: 符号链接解析后校验 Git blob，未提交的声明路径仍可借用已提交正文放行
- **评审来源**: Codex P1-51fa456-01
- **根因分析**:
  - `src/macao/workflow/orchestrator.py:414-416` 原实现先对用户声明的文档路径调用了 `.resolve()`：
    ```python
    doc_path = (self.root / doc_path_str).resolve()
    rel_doc_path = doc_path.relative_to(self.root.resolve())
    ```
  - 当攻击者在工作树创建未跟踪或恶意的符号链接（如 `docs/reviews/untracked-alias.md -> committed.md`）并在 `.dev.yml` 中将 `full_document.path` 设为该符号链接路径时，`.resolve()` 将其无感解析为其目标已提交文件 `committed.md`；
  - 随后的 `git cat-file -e` 与 `git.get_file_bytes_at_commit` 均以解析后的 `committed.md` 作为查询键，在 Git 中成功验证并放行；
  - 这导致在未将符号链接本身加入版本库的情况下，未提交路径仍可借壳已提交文件放行推进至 `READY_FOR_REVIEW`，破坏了证据文档路径在检出环境下的唯一复现性与审计不变量。
- **闭环方案**:
  1. **禁止符号链接路径解析，保留原始词法声明相对路径**:
     - 采用 `os.path.normpath` 严格词法规范化，严格拒止 `..` 遍历、空路径及逃逸出项目根目录的路径；
     - 禁止调用 `.resolve()`，直接以未解析的词法相对路径作为物理检查与 Git 查询基准；
  2. **严格排查路径链上的符号链接 (Fail-Closed)**:
     - 沿声明路径从叶子节点向根节点回溯，检查路径本身及其所有父目录（直至 `self.root`）：任一节点若为符号链接（`is_symlink()`），立即返回 `None` 拒止；
  3. **操作系统级底层防符号链接穿透**:
     - 使用 `os.lstat()` 获取文件属性，严格断言为常规物理文件 (`stat.S_ISREG`)；
     - 使用 `os.open(doc_path, os.O_RDONLY | os.O_NOFOLLOW)` 杜绝读取阶段的 TOCTOU 竞争符号链接替换；
  4. **Git 树对象文件模式（Mode）严格强校验**:
     - 在 Git 仓库环境下，除执行 `git cat-file -e` 外，增加 `git ls-tree <commit> <rel_posix>` 检视其树对象模式；
     - 严格要求对象模式必须为普通文件 blob（`100644` 或 `100755`）；若模式为符号链接（`120000`）、子模块（`160000`）或目录（`040000`），立即返回 `None` 拒止。
- **代码变更**:
  - [`src/macao/workflow/orchestrator.py`](../../src/macao/workflow/orchestrator.py)
- **测试覆盖**:
  - `tests/test_p1_closures_and_regressions.py::test_checkpoint_symlink_evidence_rejected_fail_closed` (PASS，覆盖未跟踪符号链接、已提交符号链接、父目录符号链接 3 组负向拦截场景及合法常规提交文件正向推进场景)；
  - 独立验证探针 [`docs/reviews/evidence/2026-09-10-51fa456-codex/verify_p1_51fa456_01_closed.py`](evidence/2026-09-10-51fa456-codex/verify_p1_51fa456_01_closed.py) 独立复现验证通过（退出码 0）。
