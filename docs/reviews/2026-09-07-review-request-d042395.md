### 1.1 维度一：CLI 生产就绪与交互式向导 (UX & Lifecycle Control)
- **`macao init` 智能配置向导** ([`src/macao/cli/wizard.py`](../../src/macao/cli/wizard.py))：
  - 自动读取当前项目根目录名作为项目默认名称；
  - 自动探测系统 Git 远端与默认分支（`main` / `master`）；
  - 自动扫描宿主系统已安装的原生 AI CLI，智能推荐 4 位跨模型 Reviewer 团队（如 `opencode, agy, cursor, claude`）；
  - 支持极简数字输入（如 `4`、`1-4`）、校验最低 2 席跨模型互审底线，自动计算 $2/3$ 法定仲裁阈值；
  - 生成带详尽中文用途注释的标准 `macao.yaml` 配置文件。
- **`macao clean` 隔离区治理与灾难回滚** ([`src/macao/cli/main.py`](../../src/macao/cli/main.py))：
  - 默认安全清理已完成任务的临时 Worktree 沙箱；
  - `--all` 支持一键快照备份（`.macao.bak.<timestamp>`）并安全重置运行时；
  - `--restore` 支持恢复最近一次配置与数据备份。
- **任务全周期闭环命令**：
  - `macao task checkpoint`: 支持自动/手动提审检查点，驱动进入隔离评审阶段；
  - `macao task cancel`: 支持任务撤销与工作树资源安全回收；
  - `macao merge execute`: 严格执行 fast-forward 校验并完成主干合入。

### 1.2 维度二：动态运行态探活系统 (`macao probe`)
- **原生会话定位器 `SessionLocator`** ([`src/macao/adapter/session_locator.py`](../../src/macao/adapter/session_locator.py))：
  - **零 LLM 开销的物理探测**：直接读取本地各 CLI 客户端持久化存储引擎（`agy`: `history.jsonl`、`claude`: `~/.claude/projects/`、`opencode`: `opencode.db`、`codex`: `session_index.jsonl`、`agent`: `~/.cursor/chats/`），毫秒级获取当前项目绑定的原生会话 ID 与最后活动时间；
  - 为编排器提供原生上下文恢复与断点追踪能力，避免机械重复创建空 session。
- **不介入业务底线原则与开发进度三元组 (Progress Triplet)** ([`src/macao/workflow/prober.py`](../../src/macao/workflow/prober.py))：
  - 严格遵循 [`docs/usercases/PRODUCT-FACTS.md`](../usercases/PRODUCT-FACTS.md) 与 PRD §1，MACAO 绝不代替审查员做业务语义推断，绝不捏造虚假进度；
  - 严格依托**底层物理事实**构建进度三元组：
    - `Last`: 读取 Git 历史，提取最新功能性提交（例如：`Commit 1ad706b: fix(learn): 五家评审修复批`）；
    - `Now`: 检索工作区物理提审单（`docs/reviews/*-review-request-*.md`）与代码脏改动（`Active Coding` 或 `REVIEW_PENDING`）；
    - `Next`: 比对物理提审单要求的 Reviewer 与现存 `*-review-result-*.md`，列出待落票 Reviewer 清单（`Await reviewer evaluations [...] before next commit`）。
- **审查员真实工作区探查 (True Worktree Detection)**：
  - 摒弃机械虚假占位符（如 `.macao/worktrees/<rev> (NOT_SPAWNED)`）；
  - 调用 `git worktree list --porcelain` 探查真实工作树：单仓直接评审如实展示为 **`In-repo (Shared Workspace / Direct Review)`**；独立沙箱如实展示其物理路径与 HEAD commit。
- **严格只读零副作用保证**：
  - `--dry-run` 模式强制使用 SQLite 只读 URI：`file:...state.db?mode=ro`；
  - 若当前代码库未初始化（`.macao/state.db` 不存在），**绝不擅自创建空数据库文件或执行 DDL**，保证 100% 零修改、零写锁。

## 2. 研发方法论深化：先真实环境实操演练，再沉淀完善提审（实战出真知）

在前序 `f96675f`（`404ebd2`）以及 `95b7b35` 提交阶段，团队曾登记了初步的复审申请。**该申请在此前未直接推进专家落票，绝非遗漏或疏忽，而是团队主动采取的至关重要的研发策略调整：拒绝纯纸上谈兵，坚持实践出真知**。

### 2.1 为什么必须跳出“纯纸面推演”？
多 Agent CLI 协同（跨厂商智能体、PTY 伪终端封装、进程树生命周期、Git 沙箱隔离、本地会话管理）是一门极具**物理现实约束**的系统工程：
- 如果仅停留在“文档 Schema 对齐”与“离线代码块抽检”的纸面循环中，无论文字多么完美，都无法感知真实宿主环境与复杂开发态的客观物理规律；
- 只有将编排器真正放到真实的开发项目（如 `/home/debian/english_learning_system`，已有数十轮历史评审与活跃代码提交的典型“场景 C”）中去实操运行，才能暴露那些**光靠空想根本想不到、想不透的生产级深水区难题**。

### 2.2 真实实操演练揭示的四大客观物理事实与自愈突破
正是在 `english_learning_system` 上的真机实测，倒逼团队彻底打破了此前理论假设的盲区，实现了四大关键技术突破：
1. **打破“机械空报 IDLE”的假象**：
   - *纸面盲区*：原以为 `state.db` 无任务就代表系统空闲；
   - *实战物理事实*：执行者早已在本地活跃编码，工作区有未暂存修改，且物理目录中存在等待处理的评审申请单。编排器必须依托 Git 历史与 `docs/reviews/` 物理产物，精准构建出 **`Last`（已完成提交）、`Now`（当前待审/脏代码）、`Next`（待落票评审团）** 进度三元组，既如实反映实况，又严格恪守“不介入业务”底线。
2. **打破“硬编码虚假隔离 Worktree”的臆想**：
   - *纸面盲区*：此前理论设计假设所有 Reviewer 随时都要挂载独立 Worktree，输出假路径 `.macao/worktrees/<rev> (NOT_SPAWNED)`；
   - *实战物理事实*：评审规范中 Worktree 是可选策略。单仓原地直接评审极其普遍，硬编虚假路径严重误导用户。系统全面自愈为通过 `git worktree list --porcelain` 探查真实工作树，未挂载时如实展示为 `In-repo (Shared Workspace / Direct Review)`。
3. **攻克跨 CLI 原生会话感知的“断点接续”难题**：
   - *纸面盲区*：此前未深入思考如何获知各 CLI 当前位于哪个对话中；
   - *实战物理事实*：研发出毫秒级零 LLM 开销的物理定位器 [`SessionLocator`](../../src/macao/adapter/session_locator.py)，直接读取本地会话持久化存储，精准提取 `agy`, `claude`, `opencode`, `codex`, `agent` 的活跃 Session ID。
4. **化解黑盒运行的“数据靠编”信任危机**：
   - *实战物理事实*：探活过程绝不能是黑匣子，必须具备与生产环境对账的审计留痕。系统全面实装 `.macao/logs/probe/probe_<timestamp>.log`，并提供 `macao logs --probe` 终端查阅。

### 2.3 实战闭环后的合并呈审
团队在真实环境中完成全流程验证，并将实操经验完全提炼、重构并固化为代码、测试（128 项全绿）与技术专文（[`docs/PROBE_TECHNICAL_DESIGN.md`](../PROBE_TECHNICAL_DESIGN.md)）后，**带着经过实战淬炼的高置信度物理证据重新返回评审轨道**，以当前的 `d042395` 为基准正式提交本轮合并复审申请。
