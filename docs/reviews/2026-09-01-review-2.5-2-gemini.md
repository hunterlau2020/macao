## 三、状态机与关键边界场景代数推演（SIM 推演）

### 1. 意见处置与状态流转推演（E4 vs E5a）
- **场景 A（全 Advisory 拒绝或延期）**：
  $$\text{All } requires\_new\_checkpoint == false \implies \text{E4: } CONSENSUS\_CHECK \longrightarrow MERGING$$
  - *推演*：不改变代码，不生成新 commit，原业务检查点安全合入主分支，处置留痕完整存入 Evidence Ref。
- **场景 B（任一意见采纳并要求改码）**：
  $$\exists requires\_new\_checkpoint == true \implies \text{E5a: } CONSENSUS\_CHECK \longrightarrow REWORK$$
  - *推演*：阻止直接合入，强制 Executor 产出新 commit、新 `.dev.yml` 与新申请，进入下一轮完整重评，无未审代码绕过漏洞。
- **场景 C（处置超时或请求人工）**：
  - *推演*：超时后发送 `HUMAN_OVERRIDE_REQUEST` 并停在当前状态，**绝不自动默认合并**；E7 覆盖必须附带 `exempt_issue_ids` 并生成 `override_id`，留存完整审计链。

### 2. 加权共识决策表代数推演
设配置席位 $N=3$，权重为 `codex=2, kimi=1, gemini=1`，配置总权重 $W=4$：
- 配置期检查：$\forall i, 3 \times w_i < 2 \times 4 = 8$（$6 < 8, 3 < 8$），配置合法。
- 门禁参数：席位 Quorum $\ge 2$，权重 Quorum $\ge \lceil 8/3 \rceil = 3$，胜方最少席位数 $\ge 2$。

| 票面情况 | 有效席位 / 权重 | 赞成席位 / 权重 | 反对席位 / 权重 | 判定结果 | 决策逻辑验证 |
|---|---|---|---|---|---|
| **codex(Y) + kimi(Y) + gemini(N)** | 3 席 / 4 权 | 2 席 / 3 权 | 1 席 / 1 权 | **`APPROVED`** | 赞成权重 $3 \times 3 = 9 \ge 8$ 且赞成席位 $2 \ge 2$，全部通过。 |
| **codex(N) + kimi(Y) + gemini(Y)** | 3 席 / 4 权 | 2 席 / 2 权 | 1 席 / 2 权 | **`DEADLOCK`** | 赞成权重 $3 \times 2 = 6 < 8$；反对席位 $1 < 2$，双方均未达标 $\implies$ HOLD 转人工。 |
| **codex(ABSTAIN) + kimi(Y) + gemini(Y)** | 2 席 / 2 权 | 2 席 / 2 权 | 0 席 / 0 权 | **`DEADLOCK`** | 有效权重 $2 < 3$（未达配置总权重 2/3），安全进入 `DEADLOCK`。 |
| **codex(Y) 独票（其余超时）** | 1 席 / 2 权 | 1 席 / 2 权 | 0 席 / 0 权 | **`DEADLOCK`** | 席位 $1 < 2$、权重 $2 < 3$、胜方席位 $1 < 2$，三重拦截单席位独裁。 |
