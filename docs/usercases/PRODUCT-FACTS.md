# PRODUCT FACTS：未来设计与评审锚点

本文件只记录经管理员确认的产品陈述，用于约束后续 PRD、SRS、Schema、代码、测试和评审。

本文件不声明现行实现已经满足这些产品陈述。

本文件中的产品陈述与现行规范或实现不一致时，必须通过显式变更提案完成迁移，不得把冲突静默解释为已经落地。

1. **F-1.** 角色状态表示各席位在当前任务 FSM 上的只读投影，不表示对应 CLI 是否安装、在线或空闲。

2. **F-2.** 任务级 FSM 是调度行为的唯一罗盘，CLI 自报、进程状态和终端输出只能作为旁证，不能直接替代任务状态。

3. **F-3.** State Store 只保存一个权威 `tasks.state`，Executor 和 Reviewer 不拥有可独立推进的第二套业务 FSM。

4. **F-4.** `READING_MSG` 不是业务状态，`REVIEWING` 只是 `WAITING_REVIEW` 下的席位投影，`CONSENSUS_CHECK` 不表示任务完成，`MERGING` 只表示 Git 合入流程。

5. **F-5.** 每份评审结论同时包含总体机器票和若干独立的问题或建议，不同 Reviewer 提出的事项不得因为标题相似而被编排器自动合并。

6. **F-6.** `macao init` 必须同时覆盖静态配置初始化和既有项目的动态状态接管，并在证据不能唯一推出状态时要求管理员裁定。

7. **F-7.** 评审方法以 `docs/MACAO_REVIEW_GUIDELINES.md` 为准，项目方向、评审申请、评审结论和意见处置等人可读语义证据必须在 `docs/reviews/` 中留下可由 Git 追溯的记录。

8. **F-8.** agmsg 和 AEP 是有体积预算的控制与引用通道，不是长正文仓库，也不是 FSM 事实源。

9. **F-9.** 编排器负责接收和校验任务输入，但不负责理解整体项目规划、拆分 WBS 或替项目成员制定开发内容。

10. **F-10.** 评审申请及其中的业务摘要由 Executor 撰写，Orchestrator 只补充路由、deadline、worktree、commit、路径和哈希等确定性信息。

11. **F-11.** 评审意见的语义归并以及采纳、延期或拒绝由 Executor 决定，Orchestrator 只校验结构、引用、完整性和状态守卫。

12. **F-12.** FSM 推进、法定人数判断和总体计票必须由确定性规则完成，可选 AI 只能生成诊断或候选解释，不能直接改写任务状态或机器决策。

13. **F-13.** Executor 撰写评审申请，Reviewer 撰写机器票和证据列表，Orchestrator 原样提取结构化票面并计算总体决定，Executor 负责逐条意见的语义处置且不得填写或修改总体 `decision`。

14. **F-14.** AEP 消息必须遵守版本化的字节预算，超限正文必须外置并通过受控路径、commit 和 SHA-256 引用，发送端不得静默截断内容。

15. **F-15.** `.dev.yml` 和 `.review.yml` 是结构化短信封，只保存状态转换所需字段、摘要、索引和全文引用，评审申请与评审结论的完整正文保存在 `docs/reviews/`。

16. **F-16.** Reviewer 席位可以在 `macao.yaml` 中配置管理员预先确定的 `vote_weight`，权重只影响总体机器票，不能由系统根据字数、问题数量或当轮表现自动调整，也不能替代 Executor 对单条意见的处置。

17. **F-17.** 要求合并前完成修复的“有条件通过”在机器语义上属于阻断性不通过，并进入 `REWORK`，不能以 `YES_APPROVE` 绕过重新评审。

18. **F-18.** 总体通过但仍含非阻断建议时，任务在离开 `CONSENSUS_CHECK` 前必须形成逐条处置记录，任何建议都不能因为总体通过而静默丢失。

19. **F-19.** Executor 必须通过结构化字段明确声明某项处置是否要求改变业务 checkpoint，Orchestrator 只能根据该显式字段选择进入 `MERGING` 或 `REWORK`，不能从自然语言理由推断。

20. **F-20.** 总体机器决定与逐条意见处置必须具有互不越权的写者边界和可验证的完整性边界：`vote_result.json` 为编排器单写不可变机器计票结果；`executor.disposition.yml` 为执行者单写独立处置产物（已被 PRD v2.5 D-1 / D-2 显式裁定落实）。

21. **F-21.** `docs/reviews/` 的语义留痕、SQLite 的运行时审计和 `.macao/archive/` 的机器产物归档必须同时存在并通过任务、checkpoint、round、路径和哈希相互关联。

22. **F-22.** Reviewer 权重不能取消多席位法定人数要求，也不能使单个 Reviewer 在其他有效席位反对时独自形成自动决定。
